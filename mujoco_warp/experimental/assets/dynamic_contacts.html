MuJoCo Warp already packs native contacts globally with naconmax. Savings here come from tuning that capacity. DynamicTable adds storage and adapter workspace for a copied downstream snapshot; it does not replace the solver’s contact buffers.

Fixed storage, changing contacts

Each world keeps its assigned sphere population: 1, 4, or 12. Spheres drop again after each 128-step reset. The solver’s contact count changes during each drop; object populations stay fixed.

Native contact storage and the DynamicTable are reserved at startup. The captured graph does not allocate or shrink them. A tighter global capacity needs a checked upper bound; overflow must be detected and handled.

Native physics, downstream table

This recording uses the real MuJoCo Warp collision and dynamics pipeline. Red marks show recorded sphere and plane contact points; arrows show contact normals projected into the x–z view. The browser plays the recording without simulating physics.

DynamicTable copies the existing native contact stream for downstream use. That copy and table compaction add work; native rollout timings alone do not measure this additional cost.
