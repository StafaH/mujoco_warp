API contracts, implementation paths, ownership, failure behavior, and measured tradeoffs. The report starts at the Warp runtime and follows the mechanisms up into GPU-only robot reassignment.

Part I · Warp / 01

Three mechanisms with separate responsibilities.

Warp provides storage and execution primitives. It does not know what a MuJoCo world is. The implementation separates physical memory backing, logical table mutation, and temporary storage needed to capture conditional physics.

Primitive Responsibility Execution boundary
wp.VirtualMemory Reserve contiguous CUDA virtual addresses and commit a zero-initialized physical prefix without moving the base pointer. Host construction and explicit growth; mapping mutations rejected during capture.
warp.experimental.table.DynamicTable Bounded device append/delete, stable handles, compaction, and grouping of component columns by world. Logical mutation inside graphs; physical growth outside capture and between completed replays.
wp.ScopedCaptureScratch Provide preallocated temporary storage to Python arrays and participating native allocation paths during graph construction. Suballocation and rewind at capture time; fixed addresses used during replay.

The GPU-only mjwarp loop does not request new physical pages. It prepares the model catalog, persistent arrays, Data arena, and scratch before capture. GPU kernels change logical assignments and process variable populations within that prepared storage.

Warp public surfaceVirtualMemory · DynamicTable · ScopedCaptureScratch
↓
Warp implementationPython ownership and graph integration → native CUDA bindings and allocators
↓
CUDA mechanismsAddress reservation / mapping · kernel execution · conditional graph bodies

DynamicTable is a separate ECS storage foundation. The pooled mjwarp runner uses VirtualMemory and ScopedCaptureScratch directly, with its own world worklists.

Code: warp/_src/context.py, warp/experimental/table.py, warp/native/warp.cu.

Warp / 02

VirtualMemory: stable addresses, explicit backing.

Public constructor · signature extracted from the local source

wp.VirtualMemory(size_in_bytes: int, device: DeviceLike = 'cuda', initial_size: int = 0)

size_in_bytes is the requested reservation, rounded up to the device mapping granularity. initial_size is the prefix committed during construction, and must initially lie between zero and the requested size. The device must support CUDA VMM. The tested GPU reports a 2 MiB minimum granule.

API / attribute Contract
commit(size_in_bytes) Ensure a page-rounded prefix is physically backed. Existing data and the base address remain. New pages are zeroed. A smaller request does not shrink storage; requests already satisfied return without mapping growth.
array(shape, dtype=wp.float32, offset=0) Return a contiguous zero-copy Warp view. Offset is in bytes, must be nonnegative and element-size aligned, and the entire view must fit the rounded reservation.
close() Release storage after views and graph users have been discarded. Rejects live registered array views. Already-closed reservations are a no-op.
ptr Stable base address until release.
reserved_size, committed_size, granularity Byte counts including native page rounding. Reservation is address space; commitment is physical backing.

Python → native → CUDA

  1. Create: Python validates size/device/capture state and calls wp_virtual_memory_create. Native code enters the CUDA context, checks VMM support, queries minimum granularity, and calls cuMemAddressReserve.
  2. Grow: native wp_virtual_memory_commit synchronizes the CUDA context before changing mappings. It creates physical backing for the missing suffix with cuMemCreate, maps it with cuMemMap, and sets local-device read/write access with cuMemSetAccess.
  3. Initialize and publish: new pages are cleared and synchronized before the committed size is published. The mapping retains physical-memory ownership after the temporary allocation handle is released.
  4. Release: native destruction synchronizes outstanding work, unmaps recorded spans, frees the reservation, and deletes metadata. Destruction during Warp capture can be deferred through the existing cleanup lifecycle.

Bindings are declared in warp/native/warp.h; CUDA driver entry points are loaded in cuda_util.cpp/.h. CPU-only builds expose inert native symbols so ordinary Warp initialization still works. Python rejects attempting this storage on a CPU device.

Ownership and accessible ranges

Each view stores a reference to its reservation owner. A view may describe the entire reserved range for use as a stable captured argument, but kernels must guard every access with a committed bound. Whole-view operations such as numpy(), zero_(), or copies can touch unmapped addresses. Use a committed-length view for those operations. 

import warp as wp

vm = wp.VirtualMemory(64 << 20, device="cuda:0", initial_size=4 << 20)
values = vm.array(1024, dtype=wp.float32)  # Entire view is physically backed.
pointer = values.ptr
vm.commit(8 << 20)                     # Host growth, outside graph capture.
assert values.ptr == pointer
# Retain vm/views while any graph or external tensor uses their addresses.

Array ownership is not a substitute for retaining all graph-referenced storage. Explicit close() cannot infer every external raw-pointer use. Keep the reservation or owning arrays alive for captured and borrowed tensor users.

Failure and scope: invalid sizes raise ValueError; capture/closed/native failures raise RuntimeError. Mapping failures do not publish a larger committed prefix. There is no GPU fault service, physical shrinking, peer access, CUDA IPC, or concurrent mutation of a reservation. A host mapping service must not call this synchronizing commit() while a GPU kernel waits for that service.

Implementation: VirtualMemory in context.py and native reservation/mapping functions. Design: cuda-virtual-memory.md. Semantics: CUDA driver VMM reference.

Warp / 03

DynamicTable: logical allocation inside a graph.

DynamicTable(
    columns,
    max_rows,
    num_worlds,
    initial_capacity = 0,
    device = None,
    dispatch_width = 65536,
)

columns maps component names to Warp scalar, vector, or struct types. Each component and its compaction scratch reserve a contiguous max_rows region. CUDA uses VMM; the CPU correctness path allocates maximum storage eagerly. capacity is the logical accessible prefix and can be smaller than page-rounded physical backing.

Storage Meaning
columns[name] Reserved-shape component array. Its address stays fixed through growth and compaction.
state.counters Five int32 values: extent, accessible capacity, sticky error bits, live-row count, free-list scratch counter.
world, alive, entity Per-row world ID, liveness flag, and entity slot.
slot_to_row, generation, free_slots Handle resolution, uint64 generations, and reusable entity slots.
world_offsets num_worlds + 1 offsets describing compacted world ranges; valid after compaction until the next append/delete phase.

max_rows must be between 1 and 2³¹−1. num_worlds must be positive and leave room for the offset sentinel. Launch width is fixed to min(dispatch_width, max_rows); kernels loop over device counts, allowing membership to change without graph reconstruction.

Device functions and host recording methods

API Behavior
append_row(state, world)
append_rows(state, world, count)		 Kernel-callable functions. Atomically reserve an entire contiguous batch and initialize metadata. Return the first row, or −1 with a sticky error. The producer initializes components; consumers must execute in a later kernel phase.
entity_at(state, row)
find_row(state, entity)		 Construct a handle from a valid live row; resolve a handle through its slot and generation. Deleted/recycled handles resolve to −1. entity_at expects the caller to supply a valid row.
delete_entity(state, entity) Mark a live row dead once, invalidate its slot mapping, increment its generation, and decrement live count. Returns a bool. Row storage is reclaimed by compaction.
append_worlds(counts) Host-callable, graph-recordable method. Takes device int32 counts of length num_worlds; uses an int64 prefix scan and one batch reservation. Returns device offsets, all −1 on failure. Offsets are reused by the next call.
compact() Record/enqueue grouping and compaction while preserving component addresses and surviving handles.
clear() Invalidate live handles, reset row counts and offsets, and recycle slots. Keeps physical memory and sticky errors.
ensure_capacity(rows) Host growth outside capture. Commit every region, initialize new slots, then publish logical capacity. Does not retry failed appends or clear errors.
clear_errors() Record/enqueue clearing sticky device error bits.
check_errors(), live_count Read back device counters; diagnostics outside the GPU-only loop. Errors raise on the host.
committed_bytes Owned mapped bytes plus fixed metadata/scratch; CPU storage reports its eager allocation.

Append and compaction internals

append_rows uses compare-and-swap on the row extent. It first checks world/count validity, then reserves only when the whole requested batch fits. Independent callers can succeed or fail individually; they are not one global transaction. append_worlds combines per-world counts into a single all-or-none reservation, avoiding one contended atomic reservation per entity.

Histogram live worlds→Prefix scan→Assign destinations→Gather to scratch→Copy back→Remap handles / recycle slots

Compaction keeps exported arrays in place by copying components back from persistent scratch. Relative ordering within a world is unspecified. Its cost includes scanning the row extent and committed slots, scanning world counts, and moving live component bytes. Scratch adds approximately another copy of component storage, plus metadata.

Error bits are 1 for capacity exhaustion, 2 for an invalid world ID, and 4 for a negative count. Failed appends do not grant access beyond capacity. If growth fails after some regions were committed, those regions may already have larger physical backing; logical capacity is published only after the growth sequence succeeds. 

from warp.experimental.table import DynamicTable

table = DynamicTable(
    {"position": wp.vec3, "velocity": wp.vec3},
    max_rows=1 << 20, num_worlds=8192,
    initial_capacity=8192 * 16, device="cuda:0",
)
# counts is a preallocated device int32 array of length 8192.
# During graph construction, after any needed kernel/scan warmup:
#   offsets = table.append_worlds(counts)
#   enqueue a component-initialization kernel using those offsets
#   table.compact()
# Provision enough initial capacity to keep physical growth out of replay.

Append, delete, and compact must be separate ordered phases on one stream. The prototype does not provide concurrent cross-stream mutation, automatic retry, arbitrary archetype migration, autodiff, or physical shrinking. Keep the table alive while exporting its columns; expose only safe live/committed ranges.

Code: table.py. Design: dynamic-component-tables.md. Example: example_dynamic_table.py (its standalone storage demo grows physical capacity between replays).

Warp / 04

ScopedCaptureScratch: preallocate conditional-body temporaries.

wp.ScopedCaptureScratch(buffer)

buffer must be a nonempty, contiguous, one-dimensional CUDA wp.uint8 array with fully committed storage. Native arena creation also requires 256-byte base alignment. The scope inherits the actual buffer’s memory kind rather than assuming every buffer comes from the same allocator.

CUDA conditional body graphs exclude allocation/free nodes. Existing mjwarp functions request temporary Python arrays and native scan workspace while being captured. This scope turns those requests into offsets in an already allocated buffer. CUDA conditional-body requirements

API Contract
with scratch: Install the device custom allocator and thread-local native active arena. Restore prior state on exit or failed entry. A particular scope is not reentrant.
allocate(size_in_bytes) Allocator-protocol entry. Valid only during capture on the arena’s current stream. Suballocate at 256-byte alignment; no individual allocation reclamation.
deallocate(ptr, size_in_bytes) No-op for individual slices; their storage remains owned by the backing buffer.
rewind() Reset the capture-time bump cursor. Safe only when previously recorded users finish before later users reuse those bytes. Records no replay-time allocator operation.
used_bytes Current bump offset including padding; it is not a lifetime high-water mark. The pooled runner tracks its own peak across physics branches.

Native integration and ownership

The Python scope routes Warp array creation through the allocator protocol. Native device allocation paths route matching capturing streams through wp_capture_scratch_alloc. A thread-local active-arena stack controls capture allocation, while a mutex-protected registry of live arenas recognizes their pointer ranges even after scope exit. Native frees of suballocated pointers do not free the backing memory.

Arrays retain their allocator; the allocator retains the buffer. Graphs retain the scope for native-only scratch pointers, and child/conditional graph integration propagates those references. Metadata is unregistered before releasing the backing owner. Existing retained side-stream sort workspaces continue to use their existing graph lifecycle; native scans use this scoped arena. 

# Setup: allocate persistent input/output, a device condition, and scratch.
scratch = wp.ScopedCaptureScratch(wp.empty(8 << 20, dtype=wp.uint8, device="cuda:0"))

with wp.ScopedDevice("cuda:0"), scratch:
    with wp.ScopedCapture(device="cuda:0") as capture:
        # record_phase_a/b enqueue kernels and temporary allocations.
        wp.capture_if(condition_a, record_phase_a)
        scratch.rewind()  # Phase A must finish before phase B uses these bytes.
        wp.capture_if(condition_b, record_phase_b)

# Later launches use the recorded addresses; no scratch allocation is replayed.
wp.capture_launch(capture.graph)

Integration pattern: condition_a/b and record_phase_a/b are caller-supplied. Both conditions may be true if the phases execute in order and do not retain temporary contents across the boundary.

Exhaustion is a capture failure. The native arena latches its exhausted flag; scope exit rejects the capture even if a native caller did not propagate its failure. Rewind does not clear that flag. Increase the budget or reduce the working batch and create suitable scratch before recapturing. The scope performs no physical growth.

Entering does not implicitly rewind. Alternate-stream capture must use the appropriate wp.ScopedStream. APIC recording, concurrent host allocations on the scoped device, and concurrent graph execution sharing scratch are unsupported. Scratch-created arrays must not become persistent application state across reuse boundaries.

Code: scope and graph retention in context.py, native arena and allocation/free interception. Tests: test_capture_scratch.py.

HeterogeneousWorlds: fixed model batches.

HeterogeneousWorlds(
    models: Sequence[mujoco.MjModel],
    world_model_ids: Sequence[int],
    *,
    device = None,
    data_kwargs: Mapping[int, Mapping[str, int]] | None = None,
    memory: str = 'default',
    virtual_reserve_bytes: int | Mapping[int, int] = 4 << 30,
    capacity_per_model: Mapping[int, int] | None = None,
)

The model catalog is a sequence of host mujoco.MjModel objects. Initial model IDs are a nonempty one-dimensional integer sequence. Groups are keyed by supplied model ID; equal dimensions do not imply equal dynamics. data_kwargs maps model IDs to io.make_data settings and must not override nworld.

capacity_per_model defaults to exact initial counts. An initially unused model needs explicit positive capacity to be available for GPU requests. memory="default" uses ordinary allocation; "virtual" supplies one monotonic VMM arena per group’s Data arrays. Model arrays keep the ordinary allocator. Each VMM arena aligns slices to 256 bytes, commits during construction, and retains individual frees until arena release.

Public API Semantics
groups Tuple of frozen WorldGroup objects containing model_id, device model, data, device world_ids, and arena metadata. A vacant physical slot has world ID −1.
enable_device_resets() Setup only, before any graph exists. Create templates, packed slots, mappings, and planner scratch. Return the device request array, also exposed as reset_model_ids.
reset_worlds_device(requests=None) Enqueue or record the device transaction and state initialization. Requires enabled resets. Follow immediately with action routing and physics; does not allocate or read back state.
capture(steps_per_launch=1, before_step=None, before_reset=None) Keyword-only arguments. Record episode callback → reset maintenance → action callback → physics for every group. Return the graph.
step() Replay the captured graph, or advance one timestep eagerly if no graph exists.
arrays(field) Return (world_ids, Data array) pairs. Nested Data names may use dots. These are physical group arrays; route logical worlds using device mappings.
locate(world_id), world_array(world_id, field) Host convenience lookups only before enabling GPU resets. world_array preserves a leading dimension of one and requires a world-indexed field.
inspect_layout(), memory_report() Host diagnostics outside capture. Layout inspection synchronizes/readbacks; reset-enabled memory reporting reads occupancy from device slots. 
from mujoco_warp.experimental import HeterogeneousWorlds

# Integration skeleton: models and device-work callbacks are supplied by the application.
worlds = HeterogeneousWorlds(
    models, initial_model_ids, device="cuda:0",
    capacity_per_model={0: 4096, 1: 4096, 2: 4096},
    memory="default",
)
requests = worlds.enable_device_resets()
worlds.capture(before_reset=episode_logic, before_step=route_actions)
worlds.step()

After enabling resets, world_group, world_row, and world_model_ids are authoritative device arrays. Cached host mappings must not be used. Shared model parameters and collision detection are required for this reset path; batched model parameters are rejected. Sleeping is supported by the fixed-capacity path and has dedicated state-preservation coverage.

Unused physical slots still run physics. Per-group conditional nodes skip unnecessary reset copies, but they do not make the group’s physics row count dynamic. This backend favors throughput when the population-capacity envelope is known.

mjwarp / 06

DeviceResetPlanner: transactional slot assignment.

DeviceResetPlanner(
    group_offsets,
    group_model_ids,
    model_to_group,
    slot_world_ids,
    world_group,
    world_row,
    world_model_ids,
    device = None,
)

This is a lower-level planner in mujoco_warp.experimental.device_reset, constructed by the fixed runner. All input arrays are one-dimensional int32 arrays on the selected device. Construction reads them on the host once to verify a consistent catalog and one-to-one world/slot mapping.

Input Meaning
group_offsets Length G+1; partitions a packed physical-slot array.
group_model_ids, model_to_group Group → catalog model; catalog model → group or −1 for unprovisioned models.
slot_world_ids Length S; logical world ID in each physical slot, or −1 when vacant.
world_group, world_row, world_model_ids Length N; logical-to-physical mapping. world_row is local to its group.

plan(requests) clears transaction scratch, counts selected departures/arrivals, validates destination capacity after releasing selected source slots, releases sources, builds free-row lists, and assigns destinations. Capacity is checked as: 

occupancy[group] - outgoing[group] + incoming[group] <= capacity[group]

Both sides of a full-batch swap can therefore succeed without spare slots. Unselected worlds retain their physical rows. Selected worlds, including same-model resets, may receive different rows. Assignment order is unspecified.

Device result Meaning
transaction_status int32[2]: current error bits and committed reset count.
status Sticky int32[1]: bit value 1 = invalid/unprovisioned model; bit value 2 = capacity exhaustion. clear_status() enqueues a clear.
reset_mask Length S, indexed by packed physical row. Marks released source rows and assigned destination rows.
group_reset_count Unique flagged physical rows per group; drives conditional initialization.
epoch uint64[N], incremented for each successfully reset logical world.

Invalid or over-capacity transactions preserve requests, assignments, packed slots, and epochs. Successful requests become −1. The planner itself does not initialize physics state: the runner must copy model defaults into all flagged rows before physics. Group-global contact buffers are rebuilt by physics; a policy callback immediately after reset must not consume contacts from the preceding layout.

Planning is O(N + S + G) for slot maintenance, in addition to state-copy traffic. Capture skips maintenance when no valid request exists; eager execution uses guarded launches rather than host evaluation of a conditional node. There is no host fallback or implicit growth. Mutating mappings concurrently from another stream is unsupported.

Code: device_reset.py. Tests: device_reset_test.py and runner reset tests.

mjwarp / 07

ModelWorklist: grouping without per-model capacity.

ModelWorklist(world_model_ids, num_models, device = None)

The pooled runner replaces fixed physical-slot assignment with a grouped list of logical worlds. world_model_ids is an existing int32[N] device array. Construction validates its initial values once on the host, allocates worklist scratch, and builds the initial ranges.

Validate all requests→Commit IDs / epochs→If IDs changed: histogram→Prefix model counts→Scatter world IDs

The histogram and scatter use parallel world threads and atomics. The catalog prefix sum currently uses one GPU thread looping over K models, appropriate to the prototype’s small catalog. It is not a general many-thousand-model sorting implementation.

Array / method Contract
model_worlds int32[N] grouped world IDs. Each world appears once.
model_offsets, model_counts int32[K+1] range boundaries and int32[K] population counts. Model m owns [offsets[m], offsets[m+1]).
reset_mask, epoch Logical-world mask and uint64 episode generations. Unlike DeviceResetPlanner, this mask is indexed by world, not physical slot.
plan(requests) All-or-none validation/commit; same-model requests still reset epochs/state. Captured execution rebuilds worklists only if an assignment changed. Eager calls rebuild without a host condition read.
rebuild(), clear_status() Graph-recordable worklist rebuild and sticky-error clear.
status, transaction_status Sticky invalid-model bit value 1; current [error bits, committed reset count]. No per-model capacity-exhaustion bit is needed.
workspace_bytes Planner-owned array bytes, excluding the bound world-model array.

Validation runs before assignment changes in a separate ordered kernel. One invalid request rejects the whole transaction and leaves requests pending. This atomicity describes reset metadata, not a rollback of the subsequent physics step. Existing episodes continue after rejection.

Validation scans N worlds each step. Rebuilding costs O(N + K) and uses atomic counters; there is no per-world allocation. State reset is performed by the caller after planning, on the same ordered stream.

Code: pooled_worklist.py. Tests: pooled_worklist_test.py.

These integration fields are always retained, together with requested observations. For each field, the runner finds the maximum per-world element count across models. mjwarp / 09

From startup allocation to chunk replay.

Construction

  1. Validate initial IDs, sizes, device, and requested fields. Reject sleeping-enabled models. Require collision detection and reject a Model control callback.
  2. Create one _SharedDataArena. For each model, convert the host model, rewind the arena cursor to zero, and construct io.make_data(..., nworld=B) through wp.ScopedAllocator.
  3. Commit arena pages as needed during construction. Different model layouts overlap from the same base. Arena high-water usage is the maximum constructed span, including alignment/initialization temporaries; individual frees are no-ops.
  4. Create one-world default Data for each model, reset it, and retain only fields needed to seed, reset, gather, or scatter.
  5. Allocate persistent state, worklists, request/status arrays, chunk cursors, working IDs, and scratch. Prepare flattened views and launch specifications once. Initialize every persistent world from its model defaults.

The shared arena uses VMM in this implementation, but a sufficiently sized ordinary allocation could implement the same overlapping-layout strategy. The catalog’s immutable Model arrays remain separate and ordinary-allocated.

Captured timestep

before_reset(worlds)                         # record episode producer
worklist.plan(reset_model_ids)               # validate, commit, regroup if needed
if GPU committed_reset_count != 0:
    reset selected persistent fields
before_step(worlds)                          # record policy / reset customization

for each startup catalog model:             # expanded while constructing graph
    GPU cursor = model_offsets[model]
    GPU limit  = model_offsets[model + 1]
    while GPU cursor < limit:               # device-controlled conditional body
        working_ids = next B IDs, padded with -1
        initialize working fields
        gather persistent integration state
        clear dense constraint padding
        forward.step(model, working_data)
        record sticky diagnostics
        scatter integration state and observations
        GPU cursor += B

Pseudocode. The actual implementation records wp.capture_if and wp.capture_while; it does not run Python condition checks during replay.

Per-chunk initialization

_process_chunk seeds retained fields from one-world templates, then gathers current integration state for valid working IDs. Static pose/orientation fields xpos, xquat, xmat, ximat, geom_xpos, geom_xmat, and overflow are also seeded. Vacant rows keep defaults and are excluded from scatter and logical diagnostics.

For dense models, data.efc.J and data.efc.state are zeroed before each chunk. Dense solver tiles read padded/inactive entries that ordinary Data leaves zero. Aliased layouts can overwrite those bytes. A targeted 33/35-velocity-DOF regression with active joint limits caught NaNs when those clears were omitted.

Scratch is rewound at the start of recording each model’s chunk body, and peak usage is sampled after recording its physics. At replay, repeated chunks use identical working/scratch addresses. Model branches execute sequentially; empty populations skip their physics body.

Scaling costs

Persistent storage ≈ N × sum(max model width of each retained field × element bytes)
Shared Data       ≈ page_round(max model Data-layout high-water bytes at B rows)
Scratch           = explicit startup scratch budget
Chunk count       = sum over models m of ceil(population[m] / B)

Additional costs include model arrays, defaults, mappings, and graph/runtime overhead. The current reset pass launches per-model/per-field kernels over N logical rows and the maximum field width when resets occur. It does not yet process a compact list containing only selected reset worlds. Final partial chunks still run B physics rows.

Implementation entry points: _SharedDataArena, _reset_persistent, _process_chunk, and capture in pooled.py.

mjwarp / 10

A working integration example.

The example uses six worlds, three small robot models, two working rows, and an 8 MiB scratch buffer. GPU episode logic changes the whole population at ticks 8, 16, and 24. Controls are written through stable logical-world arrays. The graph contains eight steps per launch and is replayed four times.

Source: pooled_example.py · embedded from the implementation 
"""GPU episode logic changes the entire robot population under one graph.

uv run --no-sync python -m mujoco_warp.experimental.pooled_example
"""

import json

import numpy as np
import warp as wp

from mujoco_warp.experimental import PooledHeterogeneousWorlds
from mujoco_warp.experimental.heterogeneous_device_example import _robot

wp.set_module_options({"enable_backward": False})


@wp.kernel
def _episodes(
  # In:
  tick: wp.array[int],
  # Out:
  requests_out: wp.array[int],
):
  world = wp.tid()
  if tick[0] == 8:
    requests_out[world] = 1  # Every world becomes a two-joint robot.
  elif tick[0] == 16:
    requests_out[world] = 2  # Every world becomes a three-joint robot.
  elif tick[0] == 24:
    requests_out[world] = world % 3  # Return to a heterogeneous population.


@wp.kernel
def _advance_tick(
  # Data out:
  tick_out: wp.array[int],
):
  tick_out[0] += 1


@wp.kernel
def _actions(
  # Data out:
  ctrl_out: wp.array2d[float],
):
  world, actuator = wp.tid()
  ctrl_out[world, actuator] = 0.1 * float(world + 1)


def main():
  worlds = PooledHeterogeneousWorlds(
    [_robot(1), _robot(2), _robot(3)],
    np.arange(6, dtype=np.int32) % 3,
    batch_size=2,
    scratch_bytes=8 << 20,
    device="cuda:0",
  )
  tick = wp.zeros(1, dtype=int, device=worlds.device)

  def episodes(batch):
    wp.launch(_episodes, dim=batch.nworld, inputs=[tick], outputs=[batch.reset_model_ids], device=batch.device)
    wp.launch(_advance_tick, dim=1, outputs=[tick], device=batch.device)

  def actions(batch):
    wp.launch(_actions, dim=batch.state.ctrl.shape, outputs=[batch.state.ctrl], device=batch.device)

  worlds.capture(steps_per_launch=8, before_reset=episodes, before_step=actions)
  graph, pointer = worlds.graph, worlds.state.qpos.ptr
  for _ in range(4):
    worlds.step()
  # Inspection happens only after the complete GPU-driven rollout.
  assert worlds.graph is graph and worlds.state.qpos.ptr == pointer
  np.testing.assert_array_equal(worlds.device_reset_epoch.numpy(), 3)
  assert not np.any(worlds.device_reset_status.numpy())
  assert not np.any(worlds.physics_overflow.numpy())
  assert not np.any(worlds.physics_nonfinite.numpy())
  print(
    json.dumps(
      {
        "final_model_ids": worlds.world_model_ids.numpy().tolist(),
        "resets_per_world": worlds.device_reset_epoch.numpy().tolist(),
        "same_graph_and_state_pointer": True,
        "memory": worlds.memory_report(),
      },
      indent=2,
    )
  )


if __name__ == "__main__":
  main()

The final numpy() calls are diagnostics after the rollout. They are not part of reset execution. For a learning task, the episode kernel can read termination state and select a model; the action kernel can dispatch by world_model_ids. Task-specific reward, randomization, and policy/observation schemas remain application responsibilities.

Callback contract: allocate persistent callback arrays before capture. Callbacks enqueue device work and must not make rollout decisions by reading device data on the CPU. Temporaries allocated under capture scratch must finish before physics reuses those addresses. A reset mask is available through worlds.worklist.reset_mask for device-side initialization after default reset.

To read previous episode observations, use before_reset. To write controls or customize newly reset persistent state, use before_step. Use the correct model-specific field widths. For an observation that requires forward physics at a new reset state, account for when that value becomes available rather than assuming the default template is a computed observation.

Why 2,731 rows fit the mixed case

The population is 2,731 dual-arm, 2,731 humanoid, and 2,730 single-arm worlds. A 2,731-row workspace needs one chunk per model. A 1,024-row workspace needs nine chunks total; a 4,096-row workspace still needs three but performs more vacant-row work.

Why 4,096 rows help homogeneous stages

All 8,192 worlds fit in two chunks of the active model. Empty model branches skip physics. The shared Data and scratch allocations are unchanged when the population changes.

At 2,731 working rows, persistent state is 7.63 MB, shared Data is 90.18 MB, scratch is 150.99 MB, and remaining owned arrays total approximately 0.42 MB. Methodology and comparison boundaries

RTX PRO 6000 Blackwell Workstation Edition; MuJoCo 3.12.1; local Warp 1.19.0.dev0. Primitive arm models and the repository humanoid, constant controls 0.05, timestep 0.002 seconds, Newton 10 iterations / 50 line-search iterations. Capacity: 16 contacts and 64 constraint rows per working world. Ten timesteps per graph launch. GPU episode resets every 200 steps. Each population stage has five warmup and five timed 200-step rollouts; times are CUDA-event medians. Runs were isolated from other compute tests. Every pooled run recorded zero sticky overflow/nonfinite worlds and preserved graph and persistent pointers.

These are physics measurements, not training, rendering, or policy throughput. Contact capacities must be selected for the application. Current limits

  • Logical world count, catalog topology, reset defaults, shared model parameters, and physical budgets are fixed at startup.
  • Pooled sleeping requires additional persistent derived caches and is rejected today. Control callbacks belong in the global persistent-state policy path.
  • One working arena and scratch buffer imply ordered model execution, not simultaneous independent graph execution over the same storage.
  • Active-row physics, compact selected-reset lists, more precise temporary reuse, and packed persistent fields are future optimizations.
  • Changing bodies/joints inside a model requires rebuilding model-relative metadata and kernel specializations; switching among prepared models does not implement runtime topology editing.
  • Tensor ownership and DLPack views are covered; PyTorch integration was not exercised. A complete heterogeneous task/reward/policy abstraction is outside this prototype.
